## 🛑 一、生命防线：硬件急停 vs 软件取消

> [!IMPORTANT]
> **绝对准则：在任何面对真实人流与昂贵传感器的测试场景下，软件取消永远无法替代物理硬件急停！**

```mermaid
flowchart TD
    Emergency["突发险情：机器狗前方突然冲出儿童或轮椅"]
    
    Emergency --> Soft["软件取消 (如终端按 Ctrl+C / 调用 Action Cancel)"]
    Emergency --> Hard["物理硬件急停 (遥控器急停键 / 机身物理电源按键)"]
    
    Soft -. "⚠️ 若 CPU 突发 100% 卡死或网线被绊掉，指令根本无法传达！" .-> Fail["撞击事故"]
    Hard ==> "✅ 网关板 RTOS 纳秒级切断电机驱动 H 桥供电" ==> Safe["14 关节瞬间完全卸力瘫软，确保零伤害！"]
```

| 维度 | 软件取消 (Software Cancel) | 物理硬件急停 (Physical E-Stop) |
| :--- | :--- | :--- |
| **生效层级** | 运行在计算主板的用户态应用层 | 运行在主控网关板与电机驱动板物理硬件层 |
| **触发方式** | `Ctrl+C` 信号、调用 Action 的 Cancel 接口 | 遥控器急停键、短路急停插销、物理长按机身电源 |
| **响应条件** | 要求操作系统的 CPU、网卡与进程均处于健康状态 | 无需操作系统参与，硬件逻辑纳秒级卸力 |
| **适用边界** | 日常调试、任务正常终结 | 突发异常、人身接近危险、算法失控 |

## 🚦 二、机器人工程安全“三大交通规则”

### 1. 读先于写 (Read before Write)
* 修改任何物理运动状态前，**必须先通过只读接口查询当前硬件与关节状态**；
* 检查电池电量（> 15%）、电机温度（< 70°C）与运行模式，杜绝在倾覆保护状态下强行发步态导致电机堵转烧毁。

### 2. 强制边界限制 (Bound Everything)
* **超时有界**：所有网络与服务调用强制在 `(0, 120]` 秒内，严禁 `timeout=None`；
* **队列截断**：数据接收队列严格限定为 **16**，杜绝内存膨胀 OOM；
* **禁止对写操作盲目自动重试**：运动受阻往往是因为撞到物理障碍，重试会导致齿轮打碎！

### 3. 严禁越级旁路 (Zero Bypass)
* 严禁跳过主机指纹，不可关闭 SSH 主机密钥校验；
* 严禁绕过 Aorta ACL 访问控制表；
* 保持敬畏，绝不将调试脚本直接当作无人值守生产程序。

## 🔄 三、开机自启动规范与 `flock` 防重入锁死

在实际部署中（如医院陪诊导医、巡检），我们需要机器狗开机后自动拉起 Python 业务进程。然而，错误的自启动脚本极其容易引发系统死锁甚至变砖。

### 🚨 绝对禁止的三大自启动危险操作：
1. **严禁开机无条件触发运动**：自启动脚本必须处于“待命监听状态”，严禁系统刚启动未经人工确认就自动站起走动；
2. **严禁在 `/etc/rc.local` 中直接写无超时的前台死循环**：会导致系统启动卡死在登录界面；
3. **必须显式加载环境变量**：后台守护进程不会自动加载用户 `.bashrc`，必须在脚本开头显式 `source` 环境。

## 📜 四、标准生产级开机脚本模板 (`/userdata/vbot/start_app.sh`)

官方推荐在 `/userdata/vbot/` 下维护独立部署的应用包，使用 `flock` 文件锁防止因多次触发导致并发双重运行：

```bash
#!/bin/bash
# ==============================================================================
# VBOT 生产级自启动守护脚本
# 具备：防重复启动、环境完整注入、stdout/stderr 轮转日志
# ==============================================================================

# 1. 显式加载系统与 ROS 2 环境变量
source /opt/vita/ros/humble/setup.bash
source /opt/vita/aorta/ros/local_setup.bash
export ROS_DOMAIN_ID=178
export ROS_LOCALHOST_ONLY=1
export ZENOH_SESSION_CONFIG_URI=/opt/vita/aorta/edu/edu_session.json5

# 2. 定义工作目录与日志路径
APP_DIR="/userdata/vbot/apps/my_agent"
LOG_DIR="/userdata/vbot/logs"
LOCK_FILE="/tmp/vbot_my_agent.lock"

mkdir -p "$LOG_DIR"
cd "$APP_DIR" || exit 1

# 3. 使用 flock 确保单实例运行 (防死锁与并发冲突)
exec 200>"$LOCK_FILE"
flock -n 200 || {
    echo "[$(date)] ⚠️ 程序已在运行中，杜绝重复拉起！" >> "$LOG_DIR/app.log"
    exit 1
}

echo "[$(date)] 🚀 正在启动 VBOT 具身智能主程序..." >> "$LOG_DIR/app.log"

# 4. 以后台方式拉起，并将输出重定向至日志文件
# 传入 --execute，但严禁默认加 --confirm-motion（运动需等待网络唤醒后安全确认）
exec python3 -u main.py --execute >> "$LOG_DIR/app.log" 2>&1
```

在系统开机主入口 `/userdata/vbot/init.sh` 中调用：
```bash
# init.sh 由系统在开机阶段以特权身份执行；业务进程必须显式降权到 vbot（普通用户，无 root/sudo）
nohup su - vbot -c "bash /userdata/vbot/start_app.sh" >/dev/null 2>&1 &
```

## 🌟 五、开发者工程师十条铁律

1. **先读后控**：在下发任何控制指令前，先订阅一条传感器数据确认总线真正通畅；
2. **离线优先**：所有控制代码默认提供预览模式，经过 `--confirm-motion` 显式确认才操作硬件；
3. **有界等待**：杜绝无限阻塞的 `while True`，所有网络请求必须设置超时；
4. **频率恒定**：运控发布严格维持在 10Hz ~ 20Hz，杜绝发包抖动引发看门狗刹车；
5. **算力隔离**：为运控核心保留至少 2 个 CPU 核心，高负载模型绝不占满 CPU；
6. **严禁混用**：同一时间绝不同步混用底层服务与 RCP 动作流；
7. **急停就手**：测试时操作人员的手指必须始终停留在物理急停按键附近；
8. **场地清空**：动车前确认半径 3 米内无无关人员、宠物及易碎贵重物品；
9. **环境防呆**：自启动脚本必须配合 `flock` 文件锁，绝不开机盲动；
10. **敬畏真实**：尊重每一行代码在物理世界激起的动力学回响。
