## ⚖️ 二、负重边界：额定 5kg 与极限 12kg

在加装外挂箱、AED 医疗盒、全景相机或机械臂时，必须严格遵守以下工况边界：

```mermaid
flowchart LR
    Load0["0 kg (裸机)"] --- Load5["5.0 kg (额定长期负载点)"]
    Load5 --- Load12["12.0 kg (结构安全极限)"]
    Load12 -.-> LoadFail["❌ >12 kg (严重电机过流/摔机停机)"]
```

### 1. 额定长期工作负载点：$\le \mathbf{5.0\ kg}$
* **工况表现**：底盘动态逆运动学 (IK) 与落足姿态保持最佳平衡，平地行走、爬坡（$\le 20^\circ$）与小跑姿态完全稳定；
* **重心要求**：负重重心必须严格落在机身前后轴距正中（背板中心定位孔附近），偏心距离不得超过 5cm。

### 2. 极限结构负重边界：$\mathbf{12.0\ kg}$
* **工况表现**：机器狗能完成起立与静态支撑，但小跑与急转弯时步频显著变缓，电机发热量增加；
* **开发策略**：若外挂物在 5kg ~ 12kg 之间，必须通过软件将最大线速度主动限制在 **0.2 m/s** 以下，并禁用原地急转弯与跃起等剧烈动作。

## ⚡ 三、算力隔离硬准则：为运控保留 2 个核心

> [!CAUTION]
> **一线黑客松惨痛教训**：
> 某些团队在主板上并发运行 Whisper、YOLO 与 Python 爬虫，将 8 个 CPU 核心全部跑到 100%。导致底盘核心运控进程 `locomotion_exec` 无法获取 CPU 时间片，触发 0.5s 看门狗超时，机器狗瞬间当场“四脚朝天”硬砸地面！

### 强制 CPU 亲和性隔离方案：
VBOT 的 8 个 CPU 核心中，**必须将 Core 0 与 Core 1 锁定留给系统与运控进程**。

开发者的外部算法应用，必须通过 `taskset` 绑定在 Core 2 ~ 7：
```bash
# 将你的视觉大模型推理脚本绑定在 2-7 号核心运行
taskset -c 2-7 python3 my_vision_agent.py
```
或者在 Systemd 服务守护单元中通过 `CPUQuota=600%` 进行整体资源配额截断。
