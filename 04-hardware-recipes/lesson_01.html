硬件工程规格与核心约束

预计阅读 10 分钟 · 模块 04 硬件改装与黑客松蓝本 · 前置：已熟悉基本软硬件开发

🎙️ 展开直播口播导语（讲师版）

“机器人不是纯粹的虚拟代码，任何一行失控的指令都会转化为真实的物理破坏力！在为机器狗加装外设、机械臂或运行大型模型之前，必须牢记其物理负重、供电与算力分配边界！狗背上到底能装多重？重心往哪偏会翻车？还有最致命的——为什么高负载推理时，必须给运控死死留出 2 个 CPU 核心？今天这节课，我们把这些硬核的机电物理约束一次讲透！”

本课学习目标

  • 记住整机关键规格：约 16.0 kg 自重、14 个 VGeer 关节、594 Wh 电池、8 核 ARM64 + 128 TOPS NPU
  • 分清 5.0 kg 额定长期负载与 12.0 kg 极限结构边界，知道 5.0–12.0 kg 必须限速 0.2 m/s
  • 说清为什么 Core 0–1 必须留给系统与运控，并会用 taskset -c 2-7 绑定外部算法
  • 用负载与算力规划器判断自己的改装方案是否越界

一、机体基础物理规格

在画第一根支架线之前，先把四个数字背下来：16.0 kg 的整机自重、14 个自研关节、594 Wh 的电池，以及 8 核 ARM64 + 128 TOPS NPU。它们决定了这只狗能背多重、能跑多久，还剩下多少算力留给你的算法。

参数维度规格指标工程开发警示
整机自重 约 16.0 kg（含标准电池） 搬运时请双手托举机身腹部，严禁拉扯小腿与头部
关节自由度 14 个自研 VGeer 高扭矩一体化关节（四肢各 3 + 头部 2） 头部电机主要用于视场与表情交互，不可挂载过重配重
电池容量 594 Wh 大容量动力锂电组 满电典型二开续航约 2.0 ~ 3.5 小时（视负载而定）
机身算力 8 核 ARM64 处理器 + 128 TOPS 混合精度 NPU 必须严格实施计算核心隔离（见第三节）
⚠️ 三个容易被忽略的细节
  • 受力点：搬运时双手托举机身腹部；小腿与头部是关节与减速器，不是提手。
  • 头部配重：头部 2 个电机为视场与表情交互服务，不适合当作云台挂载点。
  • 续航预算：2.0 ~ 3.5 小时是“典型二开”区间，外挂负载加重时，按 2.0 小时下限做任务规划。

二、负重边界：额定 5.0 kg 与极限 12.0 kg

外挂箱、AED 医疗盒、全景相机或机械臂上机之前，先看负载落在哪一段。机器狗不会因为你超载就立刻报警——它只会用姿态、步频和电机温度慢慢告诉你。工程上把负载划成三段：

负载包络（外挂负载，不含整机 16.0 kg 自重） 当前规划：3.0 kg · 5.0 kg 巡航区
0–5.0 kg 巡航区 额定长期点 · 全速与小跑
5.0–12.0 kg 仅瞬时冲击区 · 限速 0.2 m/s
> 12.0 kg 禁止区 电机过流 / 摔机停机
3.0
0 5.0 12.0 15 kg

横轴按 0–15 kg 等比例绘制；5.0 kg 与 12.0 kg 是两条硬边界，不是建议值。

1. 额定长期工作负载点：≤ 5.0 kg

  • 工况表现：底盘动态逆运动学（IK）与落足姿态保持最佳平衡，平地行走、爬坡（≤ 20°）与小跑姿态完全稳定。
  • 重心要求：负重重心必须严格落在机身前后轴距正中（背板中心定位孔附近），偏心距离不得超过 5cm。
±5 cm 容差带
先定重心，再定孔位
  • 中心定位孔是前后轴距的中点，也是额定负载下 IK 平衡的基准点。
  • 箱体、电池与支架围绕它对称布置，偏心距离不得超过 5cm。
  • 高位摄像头、机械臂等“高且远”的负载，应尽量靠近机身中心布置。

2. 极限结构负重边界：12.0 kg

  • 工况表现：机器狗能完成起立与静态支撑，但小跑与急转弯时步频显著变缓，电机发热量增加。
  • 开发策略：若外挂物在 5kg ~ 12kg 之间，必须通过软件将最大线速度主动限制在 0.2 m/s 以下，并禁用原地急转弯与跃起等剧烈动作。
📌 这一段不是“新的巡航档位” 5.0–12.0 kg 是仅允许瞬时冲击通过的缓冲带：能起立、能静态支撑，也能在 0.2 m/s 以下低速通过，但不能按额定负载的步态去跑。超过 5.0 kg 的每一公斤，都要用限速和动作裁剪来换。

3. 禁止区：> 12.0 kg

超过 12.0 kg 没有“慢一点就能走”的选项：这是结构安全极限之外，直接对应严重电机过流 / 摔机停机。任何加装方案称重后越过这条线，都必须先减重，再谈调试。

🚨 别用限速去“换”超载 0.2 m/s 的限速只适用于 5.0–12.0 kg 区间；超过 12.0 kg 时，风险来自结构与电机负载本身，不是靠降速就能抵消的。

三、算力隔离硬准则：为运控保留 2 个核心

负载决定狗背不背得动，算力分配决定它会不会在背得动的时候突然趴下。VBOT 机身是一颗 8 核 ARM64 处理器，核数并不宽裕，所以“谁可以用哪些核”必须是硬规则，而不是调度器的心情。

🚨 一线黑客松惨痛教训

1. 8 个核心怎么分

VBOT 的 8 个 CPU 核心中，必须将 Core 0 与 Core 1 锁定留给系统与运控进程。开发者的外部算法应用，必须通过 taskset 绑定在 Core 2 ~ 7：

Core 0系统
Core 1运控
Core 2推理
Core 3推理
Core 4推理
Core 5推理
Core 6推理
Core 7推理
运控预留 2 核 · 禁止外部算法占用 开发者可用 6 核 · 推理 / VLM / 对话
📌 记住这条分界线 Core 0–1 是系统与运控的“生命线”，Core 2–7 才是你的算法工作区。8 核里给运控预留 2 核，意味着开发者最多只有 6 个核可以把算力吃满。

2. 用 taskset 把外部算法关进 Core 2–7

启动任何视觉、语音或大模型脚本时，都在命令前加上亲和性绑定：

bash 
# 将你的视觉大模型推理脚本绑定在 2-7 号核心运行
taskset -c 2-7 python3 my_vision_agent.py
⚠️ 别只在跑大模型时才想起来 YOLO 推理、VLM、大模型对话、数据录制——只要是你自己的进程，都应该统一走 taskset -c 2-7。临时起的脚本最容易在你不注意时把 Core 0–1 吃满。

3. Systemd 配额兜底

如果外部算法以服务方式常驻，也可以在 Systemd 服务守护单元中通过 CPUQuota=600% 进行整体资源配额截断，避免单个服务把整机算力拖垮。
